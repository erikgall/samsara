# DTO Helper Catalog

**Status:** The first wave is implemented on `dev`. The complete 73-DTO audit remains the decision ledger; the other 68 valid signatures are deferred and the 27 no-helper decisions remain unchanged.

**Audit baseline authority:** `dev` at `05d3f47a948a`, the pinned 2026-08-10 Samsara OpenAPI snapshot, resource hydration paths, DTO source, and focused DTO tests at that commit. Per-row helper inventories are intentionally frozen at this baseline; the Approved first wave section records the later implementation status.

## Reconciled result

- **73/73 concrete DTOs reviewed**; `Entity` and `EntityCollection` are intentionally excluded.
- **73 unique DTOs, zero duplicates, zero omissions** across three non-overlapping domain audits.
- **46 DTOs have at least one contract-valid proposal.**
- **96 proposed method signatures** are recorded.
- **27 DTOs explicitly receive no new helper recommendation.**

## Acceptance rules applied

A helper was accepted only when it:

1. Uses fields proven on that DTO's actual endpoint payload.
2. Adds useful normalization, conversion, typed wrapping, membership, or exact state semantics beyond a raw property alias.
3. Defines behavior for missing, null, empty, zero, and unknown values where relevant.
4. Matches the package's existing helper style.
5. Has a focused test shape that would fail if the helper were implemented incorrectly.

A helper was rejected when it guessed ordering, status meaning, source precedence, authorization, geometry, or fields belonging to another endpoint.

## Reconciliation decisions

- Equipment address conveniences belong on `EquipmentGpsLocation`, not `EquipmentLocation`; the old formatted-address helper cannot return unchanged because the current address shape is `{id,name}`.
- Route-level distance, duration, edited, and pinned helpers remain rejected. Current `/fleet/routes` lacks those fields. Contract-backed distance conversions are proposed for `RouteStop`, where actual and planned meters exist.
- Trip receives only exact completion-state helpers. Its removed distance and driving-duration helpers remain invalid.
- User role convenience is based on nested role assignments, never `authType`.
- Webhook convenience is limited to event/header lookup; active/paused helpers remain invalid because webhook responses have no status field.
- DTOs with stale annotations or no current hydration path are marked with repair prerequisites instead of receiving speculative helpers.

## Implementation preconditions

Before implementing proposals on a DTO flagged as stale or unwired, first align its annotations, enum values, endpoint mapping, and existing tests. The most important discovered repairs are:

- Current alert type/status helpers, FormSubmission status helpers, Document state helpers, and DocumentType helpers use fields or values absent from the pinned contract.
- At the audit baseline, `DutyStatus::SLEEPER_BERTH` used `sleeperBerth` while current HOS payloads used `sleeperBed`; the approved first wave corrects the enum to `sleeperBed`.
- Attribute, AssetLocation, HosDailyLog, DefectType, ServiceTask, WorkOrder, CoachingSession, SafetyScore, TrailerStats, User, Webhook, and several Industrial DTO annotations do not fully match their current payloads.
- Some DTOs are not hydrated by any current resource; their rows explicitly say when mapping must precede helper work.
